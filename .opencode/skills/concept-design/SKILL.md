# Concept design (Day 3)

Follow the Build Concept stage in [the course reference](references/visual-concept-making.md). Elicit the problem, target user, context, intended value, and current understanding. Make functional and architectural feasibility assumptions explicit and link them to testable criteria. Keep desirability or viability concerns visible when raised.

Model WHAT the product must do. Define abstract logical functions and reusable types/usages, their relationships, interfaces, flows, essential user behavior, and the minimum specification for a later realization. Keep concrete technology candidates in a separate Day 4 note unless a justified requirement truly mandates them. Use a small number of alternatives where the concept is ambiguous.

Validate with the attached OpenSysML kernel when requested and create useful views using supported course syntax. Review for missing criteria links, undefined concepts, ambiguity, premature implementation choices, and alternatives. Ask the student to explain a pivotal modeling decision before calling the concept ready for Day 4. Give hints or a direct explanation on request; do not turn the session into a quiz.

For the Idea Wall, begin with abstract `Capture`, `Storage`, `Display`, and `Analytics` responsibilities. See [the runnable example and comparison prompt](references/idea-wall.md). Do not claim the example is valid until the installed course kernel returns successful execution.
