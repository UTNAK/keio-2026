# Implement PoC

Translate the concept's minimum specifications into candidate realization responsibilities. A mapping is a hypothesis, not proof that an assembly works.

For each source, record:

| Field | Meaning |
| --- | --- |
| Candidate | Exact product, library, service, or project name |
| Supplier/project | Publisher or organization |
| Version/model | Identifying version or part number |
| Evidence | Relevant documented capability or limitation |
| Source | Direct source URL and retrieval date |
| Confidence | Documentation, marketing statement, inference, or unknown |

Compare interfaces, data/power/mechanical constraints, licenses, compatibility, availability, and cost only when a current source supports it. Keep unresolved details as questions. Model the PoC separately and preserve stable concept identifiers for traceability. Prefer two materially different alternatives when credible candidates exist; explain when the evidence supports only one candidate.
